# PRD: Этап 1 — MVP

> **Этап 1 закрыт (v0.1.0).** С 16.10.2026 модель продукта другая: воркспейс → проект → приложения и сервисы, настройки на сервере Devopus, роли и вход ([vision](../docs/product/vision.md), [roadmap](../roadmap.md)). Этот PRD описывает локальный движок в словах этапа 1: «модуль» здесь — приложение.

**Статус:** в работе (вехи — [docs/stage-1/plan.md](../docs/stage-1/plan.md)); обновлён по итогам прототипов этапа 0 (14.10.2026) · **Зависит от:** успешного этапа 0 (5 команд готовы к пилоту)

## Цель

Локальный агент, который по одному файлу поднимает проект и фичи с собственными хостами. Командный слой — следующим этапом. Так ценность проверяется на реальных разработчиках до самой дорогой части разработки.

**Критерий перехода к этапу 2:** 3 пилотные команды пользуются каждый день.

## В скоупе

- Агент для **macOS** (Apple Silicon, Intel; 13+) и **Linux** (Ubuntu 22.04+, Debian 12+, Fedora).
- `workspace.yaml` v1, JSON Schema, импорт/экспорт `docker-compose.yml`.
- Базовое окружение и фичи с git worktree и своим хостом `*.localhost`.
- Маршрутизация по путям (слой 1) + **Simple Isolation** между модулями.
- Изоляция Docker (P0), порты 80/443 с тремя режимами (P0), DNS (P0), HTTPS с локальным CA (P1) и HTTP-режим.
- Клонирование БД: Postgres — база в общем инстансе через `TEMPLATE … STRATEGY FILE_COPY`; MySQL — отдельный инстанс из золотого (`CLONE LOCAL`). См. «Решения из прототипов».
- Миграции только на клонах, отставание схемы, пересоздание клона.
- Усыпление/пробуждение, бюджет ресурсов, ручное удаление с проверкой коммитов. Автоочистка `on_merge` — по локальному признаку (ветка смержена в `main` после `git fetch`), без вебхуков.
- Простая локальная веб-панель для одного разработчика + CLI.
- Runtime'ы: Docker Desktop, OrbStack, Colima — все три проверены прототипами P-1/P-2, P-3, P-6, P-7. Podman — best effort. Особенности: Colima монтирует в VM только `$HOME`; Colima и OrbStack публикуют порты на `*:порт`; на OrbStack мгновенные клоны БД (btrfs).

## Осознанно вне скоупа

Windows · командные воркспейсы · облачная панель и протокол · секреты (E2E) · межсервисная маршрутизация по заголовкам (Contextual Isolation) · превью-ссылки/Tunnel · MCP · биллинг · интеграции с таск-трекерами.

> Секреты в MVP: локальный `.env.secrets` (в `.gitignore`), подставляемый через `${{ secrets.X }}` — чтобы формат конфига не менялся при переходе на этап 2.

## User stories и критерии приёмки

### US-1. Установка
*Как разработчик, я ставлю агента одной командой и получаю рабочую среду без ручной настройки.*
- [x] `brew install` / `curl … | sh` / `.deb` / `.rpm` + `devopus agent install`. *(M9: проверено на локальной сборке; первый публичный релиз — после переименования репозитория)*
- [ ] Preflight показывает каждую проблему с владельцем и предлагаемым исправлением.
- [x] Каждое системное изменение (DNS, CA, helper) требует явного подтверждения и откатывается `devopus agent uninstall`. *(M9: служба и CA; DNS и helper в MVP не меняются)*
- [ ] На macOS 26 с Docker Desktop установка не требует root, кроме подтверждения доверия к CA в связке ключей (P-6).
- [ ] Агент никогда не слушает `0.0.0.0`. *(M3: агент слушает только unix-сокет, `127.0.0.1` (xDS) и `[::1]` (релей); Envoy опубликован на `127.0.0.1` и `::1`. Исключение, не зависящее от нас: Colima и OrbStack публикуют привилегированные порты на `*:порт` — `doctor` предупреждает)*

### US-2. Импорт проекта
*Как разработчик, я превращаю существующий compose-проект в `workspace.yaml` за минуту.*
- [x] `devopus init --from-compose` создаёт валидный черновик и отчёт о непереносимом; уровни A/B/C/N как в P-8. *(M1: 16 из 16 целевых проектов корпуса P-8 — уровень B)*
- [x] Импорт через `compose-go`: `extends`, профили, `.env`, якоря; образы без версии закрепляются по digest. *(M1)*
- [x] Экспорт обратно даёт рабочий compose для базового окружения. *(M1: проходит `docker compose config`; запуск контейнеров не проверялся)*
- [ ] VS Code подсказывает поля по JSON Schema. *(M1: схема и ссылка в шапке `workspace.yaml` готовы; заработает после публикации схемы по `schema.URL`)*

### US-3. Базовое окружение
*Как разработчик, я поднимаю весь проект с `main` и открываю его по `https://shop.localhost`.*
- [ ] Клон всех репозиториев, данные из сида/снапшота, хуки `install` → `migrate`. *(M4: клон, сборка, хуки с повтором по изменению входов готовы; сиды и снапшоты — M6)*
- [x] Фронтенд и API на одном хосте по путям; без CORS. *(M4: [examples/demo](../examples/demo) — Node `/`, Python `/api`, PHP `/admin` на `https://demo.localhost`)*
- [ ] `*.localhost` резолвится в браузере, curl, Node, Python, PHP, Java на хосте и в Python/Node/PHP внутри контейнеров (CoreDNS). Для модулей, которые ходят к своему окружению через curl или headless Chromium, — relay на `127.0.0.1:443` (P-6). *(M3: CoreDNS в каждой сети окружения работает — проверено из контейнера с Python на трёх runtime; `doctor` проверяет хост. M4: модули ходят на URL своего окружения из Node `fetch`, Python, PHP — проверено, в том числе на fallback-порту; relay для curl/Chromium не сделан — открытый вопрос M4)*
- [ ] Зелёный замок в Chrome, Safari, Firefox; curl, Python, Node, PHP в контейнерах доверяют CA без пересборки образа (переменные окружения + `bundle.pem`). *(M3: `devopus doctor --fix` ставит CA в связку ключей, страница окружения открывается в браузере без предупреждения; Chrome/Safari/Firefox по отдельности не сверены. M4: CA в контейнерах модулей (`bundle.pem` + переменные) — Node, Python, PHP доверяют и окружению, и публичным сайтам)*
- [x] Сертификат для домена вне `.localhost`, подписанный нашим CA, отвергают все клиенты, включая Java (двухуровневый CA, P-6). *(M3: схема P-6 — корень и промежуточный с Name Constraints, ключ корня не сохраняется; агент отказывается выпускать чужие имена, подпись в обход проверяется автотестом. Шесть клиентов проверены в P-6 на той же схеме)*
- [x] Сервис с `expose` доступен на `mail.shop.localhost`. *(M4)*

### US-4. Фича
*Как разработчик, я создаю фичу PAY-123 с форками `frontend` и `payments` и получаю отдельный URL.*
- [x] Worktree с веткой `feature/PAY-123` во всех выбранных репозиториях. *(M5: форки — на ветке фичи, зависимые модули — на базовой ветке в своём worktree; монорепо — один worktree репозитория)*
- [x] Клон БД форкнутых модулей из золотой копии; базовое окружение не прерывается (кроме краткого разрыва при обновлении золотой копии). *(M6: Postgres и MySQL — свой инстанс фичи из копии золотого каталога; золотая копия снимается с работающего main без разрыва — `pg_basebackup`, `CLONE LOCAL`, ADR-0007)*
- [x] При создании показывается, какие модули и БД общие с main, и подсказка форкнуть пишущие модули. *(M5)*
- [x] `https://pay-123.shop.localhost` отдаёт форки по их путям и базу по остальным. *(M5; изнутри фичи общие модули и сервисы main доступны по логическим именам через прокси)*
- [x] Две фичи не могут повлиять на контейнеры, volumes, порты и БД друг друга (интеграционный тест). *(M5: `TestFeatures` на Docker Desktop, Colima и OrbStack — свои сети, контейнеры, тома и экземпляры сервисов, правки в worktree одной фичи не видны другой)*
- [x] Время создания при 2 форках и БД 1 ГБ < 60 с (по P-3/P-4 клон БД на ext4 — 0,5–1,9 с, узкое место — диск, а не время). *(M6: 9,4 с с Postgres 1 ГБ и MySQL, включая первую золотую копию; копия 1 ГБ — 1,0 с на Docker Desktop, 0,2 с на OrbStack)*
- [x] Создание и удаление фичи не прерывает запросы к другим окружениям (xDS вместо перезапуска Envoy; P-1 показал 1,3 с простоя всех окружений при перезапуске). *(M3: xDS/SDS готовы — новая площадка добавляется без перезапуска Envoy, сеть подключается только новая; M5: тест опрашивает main каждые 20 мс, пока две фичи создаются, меняются и удаляются, — ни одного сбоя)*
- [x] Добавление модуля в существующую фичу перестраивает маршруты и перезапускает затронутые контейнеры. *(M5: `feature add`)*

### US-5. Жизненный цикл
- [x] Фича засыпает после `sleep_after` без запросов и изменений файлов. *(M7)*
- [x] Первый запрос к спящей фиче: API-запрос удерживается и доходит с телом, браузер при старте дольше 300 мс видит «Запускаем…». Накладные расходы платформы — до 0,25 с сверх загрузки приложения (P-7). *(M7: модуль, который стартует 1 с, отвечает через 1,1 с; демо с Postgres, Mailpit и тремя модулями — 1,7 с)*
- [x] Ни один запрос не теряется во время усыпления и пробуждения, включая 20 параллельных (P-7). *(M7: `TestFeatureSleep` на Docker Desktop, Colima и OrbStack — 20/20, и поток запросов во время трёх усыплений без ошибок)*
- [x] При превышении бюджета засыпает самая давно неактивная фича; база не засыпает никогда. *(M7: `features.max_running` проекта; бюджет устройства — позже)*
- [x] Удаление отказывает при незакоммиченных/незапушенных изменениях без `--force`. *(M5)*
- [x] Смерженная ветка → предложение удалить фичу (`cleanup: on_merge`). *(M7: `feature list`; squash-merge не распознаётся)*

### US-6. Миграции и данные
- [x] Миграции фичи — только на её клоне; запуск `migrate` на общей БД из фичи блокируется. *(M5–M6: при `features.database: shared` миграции модулей фичи, пишущих в общую базу, пропускаются с заметкой)*
- [x] После миграции main обновляется золотая копия; панель показывает отставание клонов. *(M6: золотая копия обновляется после изменения миграций main, `devopus db lag` показывает отстающие копии; M8: вкладка «Data» панели — отставание и сброс копии)*
- [x] `devopus db reset` пересоздаёт клон одной командой. *(M6)*

### US-7. Конфликты портов
- [x] При занятом 80/443 показывается владелец; для Herd/Valet/nginx предлагается режим сосуществования; иначе — fallback на 18443 с явной пометкой. *(M3: `status`, `doctor`, `routes`; сосуществование — `devopus proxy coexist`, проверено на Envoy)*
- [x] Конфликт на `[::1]` обнаруживается; Envoy слушает и `127.0.0.1`, и `::1` (P-6: клиенты идут на `::1` первым). *(M3; на Colima `::1` для высоких портов закрывает релей агента)*

### US-8. Локальная панель
- [x] Список окружений, фаза, URL, ресурсы, логи модулей, кнопки sleep/wake/delete. *(M8; с M9 панель — отдельный процесс, `devopus panel open` ([ADR-0012](../adr/0012-devopus-cli-control-point.md)); ресурсы — CPU и память контейнеров окружения, логи — модулей, сервисов и хуков; создание фичи из панели)*
- [x] Прогресс создания по шагам в реальном времени. *(M8: поток `Watch`)*

## Решения из прототипов этапа 0

Обязательны для реализации MVP; подробности — в отчётах прототипов.

| Область | Решение | Источник |
|---|---|---|
| Прокси | Envoy конфигурируется через xDS/SDS без перезапусков | [P-1](../prototypes/p1-p2/README.md) |
| Прокси на Mac | Envoy — контейнер; порты 80/443 публикует runtime на `127.0.0.1` и `::1` | [P-6](../prototypes/p6-dns-tls/README.md) |
| Сети | Сеть на окружение из пула `10.213.0.0/16` по `/24`; IP контейнеров модулей закреплены | P-1, [P-7](../prototypes/p7-sleep-wake/README.md) |
| Simple Isolation | Общие модули main доступны фиче через сетевые алиасы Envoy с отдельным IP в сети фичи | P-1 |
| Клон Postgres | `CREATE DATABASE … TEMPLATE golden STRATEGY FILE_COPY`; на PG 18 `file_copy_method = clone`; проверка свободного места до клона | [P-3](../prototypes/p3-db-clone/README.md) |
| Клон MySQL | Отдельный `mysqld` из золотого инстанса (`CLONE LOCAL`); `performance_schema=OFF`, маленький buffer pool | [P-4](../prototypes/p4-mysql-clone/README.md) |
| Бюджет ресурсов | Учитывает диск (клоны без reflink — полная копия) и RAM инстансов MySQL | P-3, P-4 |
| Усыпление | Здоровье фичи объявляет агент (EDS `health_status`); перед `docker stop` трафик переводится на будильник; контейнеры с `init: true` | P-7 |
| Пробуждение | Агрегатный кластер «модуль → будильник», удержанные запросы идут прямо в модуль | P-7 |
| CA | Корень с Name Constraints → промежуточный CA; ключ корня уничтожается | P-6 |
| DNS в контейнерах | CoreDNS в сети окружения; relay для curl/Chromium по требованию | P-6 |
| Импорт compose | `compose-go`, правила из [workspace-yaml.md](workspace-yaml.md#импорт-из-docker-composeyml) | [P-8](../prototypes/p8-compose-import/README.md) |
| Contextual Isolation (этап 3) | Агент не ставит `OTEL_TRACES_EXPORTER=none`; SDK для очередей; на входе удаляется только ключ `feature` | [P-5](../prototypes/p5-baggage/README.md) |

## Метрики пилота

| Метрика | Как мерить | Цель |
|---|---|---|
| Time-to-first-page (локально, без командного слоя) | от `devopus agent install` до первого 200 на базовом хосте | < 15 мин |
| DAU в пилотных командах | телеметрия (opt-in) | 3 команды ежедневно |
| Фич на разработчика в неделю | телеметрия | растёт |
| Доля фич, удалённых с ошибкой изоляции/данных | баг-репорты | 0 инцидентов потери данных |
| NPS / качественные интервью | раз в 2 недели | — |

## Ограничения, которые нужно явно сообщать пользователю

- Simple Isolation дублирует зависимые модули — больше RAM.
- Общий модуль пишет в общую БД.
- На ext4 без reflink клон БД = полное копирование: каждая фича занимает на диске размер базы.
- Фича с MySQL — отдельный процесс БД (около 120 МБ RAM и больше под нагрузкой).
- Проекты, где приложение запускается на хосте, а compose держит только инфраструктуру, пока не поддерживаются для фич (P-8).
- Фронтенд с зашитым `VITE_API_URL` не будет корректно работать в фичах — предупреждение валидатора.
