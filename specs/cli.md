# Спецификация: команда `devopus`

**Статус:** черновик; реализованы `init`, `validate`, `export compose`, `schema`, `version` (M1), `agent run`, `status`, `up`, `down` (M2), `doctor [--fix]`, `routes`, `open`, `proxy restart`, `proxy coexist` (M3), `logs`, `exec` (M4), `feature create/add/list/rm/path` (M5), `db reset`, `db golden refresh`, `db lag` (M6), `feature sleep/wake` (M7), локальная панель (M8), группы `agent` и `panel` с установкой службами (M9, [ADR-0012](../adr/0012-devopus-cli-control-point.md)). Все команды поддерживают `--json`. Файл конфига — `-f/--file`, по умолчанию `workspace.yaml` в текущей или ближайшей родительской папке.

## Принцип

**`devopus` — единая точка управления продуктом** ([ADR-0012](../adr/0012-devopus-cli-control-point.md)). Всё, что есть в Devopus, ставится, запускается, настраивается и удаляется командами `devopus`: компоненты на машине, воркспейсы и проекты, фичи, данные, конфиги. Веб-панель — ещё один интерфейс к тем же операциям.

- **Компоненты** — агент, локальная панель, позже сервер — независимы. У каждого своя группа команд с одинаковым набором действий: `install`, `start`, `stop`, `restart`, `status`, `logs`, `uninstall`, `run`.
- **Один бинарник:** все компоненты — подкоманды `devopus` одной версии. Компонент другой версии (после обновления) CLI перезапускает сам.
- **Команды, которым нужен агент, запускают его сами:** через службу, если она установлена, иначе в фоне.
- `devopus --help` показывает команды по группам и как начать работу.

## Агент

Агент на этой машине: приводит Docker к состоянию, описанному проектами. Говорит с CLI и панелью через unix-сокет `~/.devopus/agent.sock`.

| Команда | Описание |
|---|---|
| `devopus agent install [--yes]` | Регистрирует агента службой пользователя (launchd agent на macOS, systemd user unit на Linux): старт при входе, перезапуск после падения. Останавливает агента, запущенного в фоне, запускает службу, прогоняет `doctor` и предлагает доверить CA. Каждое системное изменение — с подтверждением; без терминала — код 3, если нет `--yes`. Повторный запуск обновляет путь к бинарнику. Privileged helper в MVP не нужен ([ADR-0011](../adr/0011-privileged-helper.md)) |
| `devopus agent start` / `stop` / `restart` | Запустить (через службу или в фоне), остановить, перезапустить. Остановка агента не останавливает окружения; следующая команда, которой нужен агент, запустит его снова |
| `devopus agent status` | Работает ли агент, версия, pid, служба, каталог данных, сокет, лог |
| `devopus agent logs [--follow] [-n N]` | Лог агента |
| `devopus agent uninstall [--purge] [--yes]` | Останавливает все окружения (данные остаются), снимает службу и агента, останавливает прокси и DNS, вынимает CA из связки ключей (на Linux печатает команды). `--purge` — ещё и окружения с данными, локальная панель и `~/.devopus`; checkout'ы с несохранённой работой остаются в `~/.devopus/src`. Бинарник остаётся: его удаляет то, чем ставили (`brew uninstall devopus`) |
| `devopus agent run` | Агент на переднем плане — то, что запускает служба; для отладки |

## Панель

Локальная веб-панель: окружения этой машины, прогресс, логи, данные, фичи. Это отдельный процесс на `127.0.0.1`: он отдаёт веб-приложение и пересылает его запросы агенту. Агент работает без панели, а панель без агента показывает «агент не отвечает» и ждёт его. Файлы — в `~/.devopus/panel/`.

| Команда | Описание |
|---|---|
| `devopus panel open [--no-open]` | Открыть панель в браузере уже авторизованной (ссылка с токеном работает только на этом устройстве). Запускает панель, если она не запущена. `--no-open` — напечатать ссылку |
| `devopus panel install [--port N] [--yes]` | Панель службой пользователя: старт при входе. `--port` — закрепить порт (по умолчанию — прежний или свободный) |
| `devopus panel start` / `stop` / `restart` | Запустить, остановить, перезапустить панель; агент и окружения не затрагиваются |
| `devopus panel status` | Работает ли панель, адрес, версия, служба, лог |
| `devopus panel logs [--follow] [-n N]` | Лог панели |
| `devopus panel uninstall [--yes]` | Остановить панель, снять службу, удалить её файлы и токен: вошедшие браузеры теряют доступ |
| `devopus panel run [--port N]` | Панель на переднем плане — то, что запускает служба |

## Машина

| Команда | Описание |
|---|---|
| `devopus status` | Агент, runtime, прокси (режим портов default / coexist / fallback, владельцы занятых портов, связь с Envoy), CA и доверие к нему, панель, окружения с URL |
| `devopus doctor [--fix] [--yes]` | Preflight-проверки (Docker, агент, панель, порты 80/443 v4/v6, DNS, CA, пулы адресов) с владельцами конфликтов и предложениями исправлений. `--fix` делает то, что Devopus умеет сам (CA в связку ключей macOS), спрашивая перед каждым; без терминала — код 3, если нет `--yes`. Код 4, если есть ошибки |
| `devopus proxy restart` | Пересоздать прокси: он заново проверит 80/443 (URL меняются, если меняются порты) |
| `devopus proxy coexist --http <port> [--https <port>]` / `--off` | Режим сосуществования: dev-сервер (Herd, Valet, nginx) перенесён на другие порты, Devopus занимает 80/443 и отдаёт ему все незнакомые хосты (HTTPS — без расшифровки) |
| `devopus version` | Версия |

## Проект

| Команда | Описание |
|---|---|
| `devopus init [--from-compose <file>]… [--project <name>] [--no-pin] [--force]` | Создать `workspace.yaml` в текущей папке (она — корень репозитория). Без `--from-compose` берёт `compose.yaml`/`docker-compose.yml` из папки, если есть, иначе пишет шаблон. Несколько `--from-compose` сливаются как `docker compose -f`. Плавающие теги закрепляются по digest из реестра (`--no-pin` — пропустить). Секреты — в `.env.secrets`. Отчёт с уровнем A/B/C/N; код выхода 2 при уровне C |
| `devopus validate` | Проверка по JSON Schema и правилам + антипаттерны |
| `devopus export compose [-o file]` | Экспорт в `docker-compose.yml` (по умолчанию в stdout); откажет, если конфиг с ошибками |
| `devopus schema` | Напечатать JSON Schema `workspace.yaml` |
| `devopus up [-d] [--timeout]` | Поднять базовое окружение (clone репозиториев, образы, сервисы, хуки, модули, маршруты); показывает прогресс шагов и в конце — адреса модулей и сервисов. `-d` — не ждать. Повторный `up` без изменений ничего не перезапускает |
| `devopus down [--volumes] [--project]` | Остановить окружения проекта; `--volumes` — удалить проект со всеми ресурсами и данными |
| `devopus open [env]` | Открыть URL в браузере; без аргумента — базовое окружение проекта из `workspace.yaml` |

## Фичи

| Команда | Описание |
|---|---|
| `devopus feature create <name> -m a,b [--branch …] [-d]` | Создать фичу: worktree форков на ветке `features.branch_prefix + name` (или `--branch`; существующая локальная ветка или ветка из `origin` подхватываются), URL `https://<slug>.<domain>`. До создания печатает, что фича запускает сама, что берёт у базового окружения, и подсказку форкнуть общий модуль, который пишет в данные main. Затем — прогресс, как у `up`. Нужен запущенный или запускаемый `up` базовый вариант: `create` поднимает и его. *`--from-task URL` — этап 2+* |
| `devopus feature add <name> <module>…` | Форкнуть ещё модули: worktree модуля переходит на ветку фичи, маршруты, DNS и контейнеры перестраиваются |
| `devopus feature list [--all]` | Фичи проекта (или всех): фаза (`sleeping (idle/budget/manual)`), последняя активность, URL, форки, ветка (`merged`, если слита в базовую — с подсказкой `feature rm`), что общее с main |
| `devopus feature sleep <name>`, `devopus feature wake <name>` | Усыпить фичу (контейнеры останавливаются, первый запрос будит её) или разбудить заранее. Сама фича засыпает после `features.sleep_after` без запросов и правок кода |
| `devopus feature rm <name> [--force]` | Удалить контейнеры, тома, сеть и worktree фичи. Без `--force` откажет, если в worktree есть незакоммиченные изменения или коммиты, которых нет ни на удалённом репозитории, ни в базовой ветке. Ветка остаётся в любом случае |
| `devopus feature path <name> [module]` | Папка проекта в worktree фичи или папка модуля (для IDE и AI-агентов: `code $(devopus feature path PAY-123)`) |

`[env]` в `logs`, `exec`, `routes`, `open` принимает ID окружения, слаг или имя фичи.

## Данные

| Команда | Описание |
|---|---|
| `devopus db golden refresh [service]…` | Снять золотые копии баз main заново, с данными, что в main сейчас. Сам агент делает это, когда фиче впервые нужна копия и после изменения миграций main |
| `devopus db reset <feature> [service]…` | Выбросить данные фичи и скопировать золотую копию заново; миграции фичи идут на новой копии. Без сервисов — все базы фичи |
| `devopus db lag` | Золотые копии main и копии фич: когда сделаны, размер, отстаёт ли копия фичи от золотой |

## Отладка

| Команда | Описание |
|---|---|
| `devopus logs [env] <module\|service> [--follow] [-n N]` | Вывод модуля, воркера или сервиса. С одним аргументом — базовое окружение проекта из текущей папки. `-f` занят под `--file`, поэтому только `--follow`. Логи хуков и сборок — в `~/.devopus/envs/<env>/logs/` |
| `devopus exec [env] <module\|service> [-- <cmd>…]` | Выполнить команду в контейнере (по умолчанию `sh`); с терминалом — интерактивно |
| `devopus routes [env]` | Текущая таблица маршрутов Envoy: URL, путь, окружение, цель |

## Коды выхода

`0` успех · `1` ошибка · `2` неверные аргументы/конфиг · `3` требуется подтверждение (в неинтерактивном режиме) · `4` preflight не пройден.

## Дальше (этапы 2–4)

Всё новое сначала проектируется как команды `devopus`, потом как экраны панели. Набор действий у компонентов тот же, что у `agent` и `panel`.

| Команды | Этап | Что |
|---|---|---|
| `devopus login` / `logout` / `whoami` | 2 | Вход на сервер Devopus (device flow, RFC 8628); `--server URL` — для self-hosted |
| `devopus workspace create` / `list` / `use` / `invite` / `members` / `roles` | 2 | Воркспейс команды, участники и роли; владелец окружения меняет стек команды |
| `devopus project create` / `list` / `link` / `sync` / `rm` | 2 | Проекты воркспейса: создать из `workspace.yaml`, привязать репозиторий, двусторонняя синхронизация конфига с git. Сейчас проект появляется на машине при первом `devopus up` |
| `devopus agent install --server` | 2 | Агент на сервере команды или хостинге: системная служба, подключение к серверу Devopus, без локальной панели |
| `devopus agent list` / `revoke` | 2 | Устройства воркспейса и отзыв устройства |
| `devopus secrets set` / `list` / `rm` / `rotate` | 2 | E2E-секреты воркспейса |
| `devopus drift` | 2 | Расхождения окружений участников с конфигом команды |
| `devopus config get` / `set` / `list` | 2 | Настройки компонентов и воркспейса (порты, политики) в одном месте |
| `devopus snapshot build` | 2 | Обезличенный снапшот данных для онбординга (в CI клиента) |
| `devopus mcp` | 3 | MCP-сервер (stdio) для AI-агентов: `list_projects`, `create_feature`, `feature_status`, `feature_url`, `feature_logs`, `delete_feature` |
| `devopus server install` / `upgrade` / `status` / `backup` / `uninstall` | 4 | Self-hosted сервер: Core, Agent gateway, Tunnel и удалённая панель у клиента |
