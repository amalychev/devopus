# ADR-0020: Окружения на серверах админа — публичный домен, подписанный создателем, и сертификат Let's Encrypt от агента

**Статус:** Accepted (17.10.2026). Этап 5, шаг R14a (staging). Production — R14b.

## Контекст

После R13 ([ADR-0019](0019-admin-servers.md)) сервер админа запускает проекты только по локальному адресу (`*.localhost`) самого сервера. Для staging нужен публичный адрес с настоящим сертификатом. При этом сервер применяет только то, что подписали доверенные люди: адрес, на котором проект виден из интернета, — тоже часть «что запускается», и брать его со слов сервера воркспейса нельзя.

## Решение

1. **Окружение — проект на сервере с публичным доменом:** `devopus env create staging --project shop --server stage --domain staging.shop.example.com` (право `servers.manage` в проекте и во всех проектах этого сервера). Домен проверяется: имя из интернета, не `.localhost`/`.local`/`.test`, не IP; один домен — одно окружение на всю инсталляцию.
2. **Создатель подписывает окружение** ключом своего устройства (`signing.EnvironmentMessage`: воркспейс, сервер, проект, вид, домен). Агент сервера принимает домен, только если подпись проверяется по его корню доверия. Неподписанное или подменённое окружение оставляет прежний домен.
3. **Ветка — из подписанных настроек проекта.** Отдельной «ветки окружения» нет: иначе сервер воркспейса мог бы незаметно переключить сервер на другой код.
4. **Наружу — только главный адрес проекта.** Веб-интерфейсы сервисов (админка базы и т. п.) на сервере не публикуются.
5. **Сертификат получает агент сервера** у Let's Encrypt по ACME (`internal/agent/acme`, `golang.org/x/crypto/acme`) с проверкой HTTP-01. TLS завершает Envoy, поэтому TLS-ALPN не подходит. На порту 80 Envoy отправляет `/.well-known/acme-challenge/` агенту на хосте до перенаправления на https. Сертификат и ключ аккаунта хранятся в папке агента; продление — за 30 дней до конца срока. После неудачи повтор не раньше чем через 10 минут, чтобы не выйти за лимиты Let's Encrypt. Пока сертификата нет, сайт отдаётся с временным самоподписанным.
6. **Прокси сервера публичен.** На машинах разработчиков прокси публикуется только на loopback. На сервере — на всех адресах, порты 80 и 443, без режима сосуществования.
7. **Агент на Linux слушает адрес моста Docker.** Свои порты для контейнеров (xDS, будильник, ACME) агент открывает на `host.docker.internal`: на Docker Desktop, OrbStack и Colima это loopback, а на Linux-движке — шлюз моста (`docker0`). Этот адрес доступен контейнерам, но не сети.

## Последствия

- Staging админа живёт по `https://staging.shop.example.com` с сертификатом, который обновляется сам. Админ только направляет DNS на сервер и держит открытыми порты 80 и 443.
- Подменить адрес или ветку staging, взломав сервер воркспейса, нельзя.
- **Пока не сделано (R14b):** production — отдельное право, запуск только явно выкаченной и подписанной версии, откат выкаткой прежней, обновление без простоя.
- **Не проверено на настоящем Linux-сервере:** прослушивание на мосту Docker (при включённом `ufw` нужно разрешить вход с `docker0`), публикация на всех адресах, выдача сертификата настоящим Let's Encrypt.
