# ADR-0012: Команда `devopus` — единая точка управления; агент и панель — отдельные компоненты

**Статус:** Accepted (16.10.2026)

## Контекст

До этого решения локальная панель (M8) была частью агента: агент сам слушал порт панели, а `devopus install` ставил «агента вместе с панелью». Но в будущем у продукта несколько частей, и живут они в разных местах:

- **агент** — на ноутбуке разработчика, на сервере команды, на хостинге (staging);
- **панель** — локальная на `127.0.0.1` сейчас, удалённая командная панель с этапа 2, self-hosted с этапа 4;
- **сервер** (Core, Agent gateway, Tunnel, [ADR-0002](0002-modular-monolith-three-deploys.md)) — в нашем облаке или у клиента.

Панель, вшитая в агента, не переносится на сервер. Безопасники не могут закрыть её порт, не останавливая агента. У тимлида, который ведёт окружение команды, нет одного инструмента, через который он управляет всем.

## Решение

1. **`devopus` — единственный инструмент управления.** Всё, что есть в продукте, ставится, запускается, настраивается и удаляется командами `devopus`: компоненты на машине, воркспейсы, проекты, фичи, данные, конфиги. Веб-панель — ещё один интерфейс к тем же операциям, а не место, где есть что-то, чего нет в CLI.
2. **Каждый компонент — своя группа команд с одинаковым набором действий:** `install`, `start`, `stop`, `restart`, `status`, `logs`, `uninstall`, `run` (на переднем плане — то, что запускает служба).
   - `devopus agent …` — агент. Сейчас локально; с этапа 2 — `devopus agent install --server` для серверов (системная служба, подключение к серверу Devopus).
   - `devopus panel …` — панель. Сейчас локальная; с этапа 2 удалённая панель — часть сервера.
   - `devopus server …` — сервер Devopus для self-hosted (этап 4).
3. **Компоненты не зависят друг от друга при запуске.** Агент работает без панели. Локальная панель — отдельный процесс (`devopus panel run`), который отдаёт веб-приложение и пересылает его запросы в API агента по unix-сокету. Если агента нет, панель отвечает «unavailable» и ждёт его. Удалённая панель ходит к агентам через сервер, а не на их машины.
4. **Один бинарник.** Все компоненты — подкоманды одного `devopus`: одна установка, одна версия. Компонент другой версии CLI перезапускает сам.

## Последствия

- `devopus install`, `devopus uninstall` и `devopus ui` заменены на `devopus agent install`, `devopus agent uninstall` и `devopus panel open`. Пользователей ещё нет, поэтому совместимость не нужна.
- Агент больше не знает о панели: поле `panel_url` удалено из `StatusResponse`. Адрес панели CLI берёт у самой панели (`/healthz`).
- Файлы панели лежат отдельно, в `~/.devopus/panel/` (порт, токен, блокировка, лог). `devopus panel uninstall` удаляет их вместе с токеном, и браузеры теряют доступ.
- `devopus agent uninstall --purge` удаляет и локальную панель: её файлы лежат в каталоге агента.
- Новые возможности (воркспейсы, секреты, серверы) сначала проектируются как команды `devopus`, затем как экраны панели. Список будущих команд — в [specs/cli.md](../specs/cli.md#дальше-этапы-24).
