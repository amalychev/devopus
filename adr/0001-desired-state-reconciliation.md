# ADR-0001: Желаемое состояние вместо команд

**Статус:** Accepted

## Контекст
Агент работает на ноутбуках с нестабильной связью, засыпанием, переподключениями. Одноразовые команды теряются и приводят к частично применённым операциям.

## Решение
Сервер (или локальный файл в MVP) хранит **желаемое состояние** устройства с монотонной ревизией. Агент в reconcile-цикле наблюдает фактическое состояние (по Docker-меткам, `git worktree list`, конфигу Envoy) и выполняет идемпотентные шаги до сходимости. Разовые `Action` — только из белого списка и только для операций, не выражаемых состоянием (снапшот, рестарт).

## Последствия
- Потеря сообщения не ломает систему; после переподключения агент доделывает операции.
- Работа без интернета по кэшированному состоянию.
- Каждый шаг обязан быть идемпотентным; нужен тщательный GC по меткам.
- Те же сообщения (`DesiredState`/`StatusReport`) используются локальным API в MVP — облако добавляется без переписывания агента.
