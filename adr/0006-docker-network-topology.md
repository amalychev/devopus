# ADR-0006: Топология docker-сетей

**Статус:** Accepted по итогам P-2 (14.10.2026): вариант A — сеть на окружение

## Контекст
Пул адресов Docker по умолчанию исчерпывается примерно после 30 сетей; подсети 172.17–172.31 пересекаются с корпоративными VPN.

## Варианты
| Вариант | Плюсы | Минусы |
|---|---|---|
| A. Сеть на окружение | Простая изоляция, одинаковые имена (`mysql`) в каждой сети | Быстро съедает пул; Envoy подключается к десяткам сетей |
| B. Сеть на проект + алиасы по ID окружения | Экономит пул | Логические имена резолвятся через Envoy/CoreDNS, а не напрямую; сложнее |

## Рекомендация
B с `default-address-pools` `10.213.0.0/16` /24 и проверкой пересечения с маршрутами хоста. Если прототип покажет сложность с логическими именами — A с тем же пулом (256 сетей).

## Результат прототипа P-2 (14.10.2026)
Сеть на окружение (вариант A) с пулом `10.213.0.0/16` по `/24` работает: 255 окружений на машину, пул не узкое место. Общие модули main доступны фиче через алиасы Envoy с отдельным IP в сети фичи, без двусмысленного DNS. **Рекомендация меняется на A.** Подробно — [prototypes/p1-p2/README.md](../prototypes/p1-p2/README.md).
