# ADR-0008: Где хранить `workspace.yaml`

**Статус:** Superseded by [ADR-0013](0013-config-on-workspace-server.md) (16.10.2026): настройки живут на сервере воркспейса; в папке проекта — только личный `devopus.yaml` с переопределениями, в git он не попадает.

| Вариант | Плюсы | Минусы |
|---|---|---|
| Отдельный репозиторий конфига | Проект из нескольких репозиториев описан в одном месте; права на изменение инфраструктуры отдельно | Ещё один репозиторий; изменения кода и инфраструктуры в разных PR |
| Основной репозиторий проекта (или монорепо) | Конфиг меняется вместе с кодом в одном PR | Какой репозиторий «основной» при 3+ модулях — неочевидно |
| Гибрид: проектный файл + `devopus.module.yaml` в каждом модуле | Модуль сам описывает runtime/hooks, проект — композицию | Сложнее формат и синк |

## Что учесть
- Двусторонняя синхронизация с панелью (правка в панели = коммит) — проще с отдельным репозиторием.
- Фича, меняющая инфраструктуру модуля (новый сервис) — проще с конфигом в репозитории модуля.

Интервью этапа 0 закрыты без ответа на этот вопрос. Решить по пилотным командам (их compose-файлы и структура репозиториев, V-4); до этого MVP поддерживает оба варианта.
