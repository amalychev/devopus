# ADR-0011: Privileged helper и запрет 0.0.0.0

**Статус:** Accepted; уточнён по итогам P-6 (14.10.2026)

## Контекст
На macOS с Mojave порт < 1024 без root открывается только на `0.0.0.0`, что делает окружения с данными доступными всей LAN. Также нужны права для DNS (`/etc/resolver`, NRPT) и установки CA.

## Решение
- Агент работает без root. Минимальный helper: launchd-демон (macOS), Windows Service, на Linux — `setcap cap_net_bind_service` на прокси (иначе rootful dockerd, иначе sysctl с согласия).
- Helper открывает `127.0.0.1:80/443` и `[::1]:80/443` и передаёт сокеты через socket activation; принимает только типизированные запросы.
- **Никогда не слушать `0.0.0.0`.**
- Чужие службы не останавливаются без подтверждения; при конфликте — режимы «сосуществование» и fallback (18443).

## Результат прототипа P-6 (14.10.2026)
- Подтверждено на macOS 26: без root `127.0.0.1:81` и `[::1]:81` — отказ, `0.0.0.0:81` — можно.
- **Docker Desktop без root публикует `127.0.0.1:81` и `[::1]:81`.** Поэтому на Mac с Docker Desktop Envoy работает контейнером, и свой launchd-помощник для портов не нужен. Помощник остаётся для случая «Envoy на хосте» и для runtime, которые так не умеют (OrbStack и Colima не проверены).
- macOS 26 резолвит `*.localhost` без `/etc/resolver`, так что root на macOS 26 может не понадобиться вовсе. Остаётся только установка CA в связку ключей, а для неё достаточно подтверждения пользователя.
- Linux: `setcap cap_net_bind_service=+ep` на бинарник прокси проверен.
- Подробно — [prototypes/p6-dns-tls/README.md](../prototypes/p6-dns-tls/README.md).

### Дополнение: Colima и OrbStack (14.10.2026)
Оба публикуют привилегированные порты без root, но слушают `*:порт`, а не `127.0.0.1` (трафик с LAN не пересылают). Если пользователь требует строгий `127.0.0.1` на этих runtime, нужен launchd-помощник; по умолчанию агент предупреждает в `doctor`.
