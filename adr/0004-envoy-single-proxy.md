# ADR-0004: Один Envoy на устройство

**Статус:** Accepted

## Решение
Все проекты устройства обслуживает один Envoy на одном порту с маршрутизацией по hostname, path и (этап 3) baggage. Конфигурация — через xDS/SDS от агента (`go-control-plane`) без перезапуска. Envoy — единственный TLS-терминатор; сертификат с SAN выпускается на каждый хост.

## Альтернативы
- Caddy/Traefik — проще, но слабее динамическая маршрутизация по заголовкам и xDS.
- Прокси на проект — лишние порты и конфликты.

## Последствия
- Детектор активности и hold-запросов при пробуждении реализуются на Envoy (access log, stats, retry/hold-фильтр или ext_proc).
- Envoy слушает 127.0.0.1 и ::1 (никогда 0.0.0.0).

## Результат прототипа P-1 (14.10.2026)
Перезапуск Envoy при каждом изменении маршрутов обрывает запросы ко **всем** окружениям примерно на 1,3 с. xDS/SDS без перезапуска обязателен уже в MVP.
