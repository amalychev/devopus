# ADR-0005: Simple Isolation в MVP, Contextual — на этапе 3

**Статус:** Accepted

## Контекст
Маршрутизация по W3C Baggage — ключевое отличие продукта, но автоматическая передача контекста не гарантирована (нестандартные клиенты, PHP без расширения, очереди, cron, WebSocket/gRPC). Изоляция данных важнее экономии ресурсов.

## Решение
- **Simple Isolation** (MVP, legacy): фича получает свои контейнеры для изменённых и зависимых модулей; адреса — через `${{module.url}}`.
- **Contextual Isolation** (этап 3): Envoy маршрутизирует по контексту фичи; базовые модули общие. Входящий baggage-ключ фичи удаляется на границе и выставляется прокси. Проверка распространения через OTel.
- Прототип Contextual — на этапе 0 (главная гипотеза).
- Режим задаётся на уровне проекта (`features.isolation`) и может переопределяться на фиче; WebSocket/gRPC/TCP-модули всегда в Simple.

## Последствия
- MVP дороже по RAM, но предсказуем.
- Формат `workspace.yaml` с первого дня использует логические имена (`http://payments`) — переход к Contextual не требует правок проектов.
