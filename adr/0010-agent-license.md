# ADR-0010: Лицензия агента

**Статус:** Accepted (14.10.2026): Apache 2.0 для агента, формата `workspace.yaml` и JSON Schema

| Лицензия | Плюсы | Минусы |
|---|---|---|
| Apache 2.0 | Максимальное доверие безопасников и сообщества, патентный грант | Облачные провайдеры могут построить конкурирующий сервис |
| BSL (Business Source License) | Защита от коммерческого копирования, переходит в open-source через N лет | «Не совсем open-source», часть сообщества отталкивает |
| FSL (Functional Source License) | Короткий период (2 года) → Apache/MIT; понятнее BSL | Тот же класс возражений |

## Соображения
- Цель открытости — аудит безопасниками, рост через разработчиков, отсутствие lock-in. Все три варианта позволяют читать код.
- Ценность и монетизация — в командном слое (закрытый), а не в агенте.
- Формат `workspace.yaml` и JSON Schema — в любом случае под permissive-лицензией.

Предварительная рекомендация: Apache 2.0 для агента и схем; решение — до публичного релиза.

## Решение (14.10.2026)
**Apache 2.0** для агента, схем Protobuf и JSON Schema `workspace.yaml`. Командный слой (Core, Agent gateway, Tunnel, панель) — проприетарный.

Почему: цель открытости — аудит безопасниками и доверие разработчиков. BSL/FSL дают формальную защиту от копирования, но ослабляют именно это доверие. А монетизация и так лежит в командном слое, а не в агенте.

На интервью вопрос Д2 всё равно задаём: если окажется, что лицензия важна иначе, чем ожидали, решение пересматривается до публичного релиза агента.
