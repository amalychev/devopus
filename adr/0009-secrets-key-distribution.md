# ADR-0009: Доставка ключа воркспейса на новое устройство

**Статус:** Accepted (16.10.2026), реализовано в R8 ([план рефакторинга](../docs/refactoring-plan.md))

## Контекст
Секреты зашифрованы E2E ключом воркспейса (X25519). Новое устройство должно получить ключ, не раскрывая его серверу, иначе онбординг < 15 мин не достижим.

## Варианты
A. Онлайн-устройство админа автоматически оборачивает ключ для нового устройства.
B. Общий сервер команды (Device на уровне Workspace) — key custodian.
C. Recovery-ключ: админ вводит его и оборачивает ключ для устройства.

## Решение

**A + запасной C.**

1. **Криптография — age (X25519).** У воркспейса пара ключей, у каждого устройства своя. Приватный ключ устройства — в системном хранилище ключей рядом с refresh-токеном (Keychain, Secret Service; файл `0600`, где их нет). Сервер хранит публичный ключ воркспейса, его приватный ключ, обёрнутый для каждого устройства, и шифртексты. Значений и приватных ключей он не видит.
2. **Задать секрет** может любой с `secrets.manage`: для шифрования нужен только публичный ключ. Первый секрет создаёт ключ воркспейса на устройстве админа; ему один раз показывается **код восстановления** — приватный ключ воркспейса.
3. **Доставка (A):** агент устройства сообщает серверу свой публичный ключ. Серверу известны устройства, которым ключ ещё не дошёл; он сообщает их агентам админа и тимлидов, у которых ключ уже есть. Те оборачивают ключ для этих устройств сами, без действий людей.
4. **Запасной путь (C):** `devopus secrets recover` — код восстановления ставит ключ на это устройство; дальше его агент доставляет ключ остальным.
5. **Ротация** — `devopus secrets rotate` на устройстве админа: новый ключ, все секреты перешифровываются там же и оборачиваются для устройств текущих участников, старые обёртки удаляются. При удалении участника его ключи устройств и обёртки удаляются сразу; ротацию админ запускает сам.
6. **Ключ один на воркспейс.** Кому какие шифртексты отдавать, решает сервер по праву `secrets.read` в проекте.

## Последствия
- Вариант A доверяет серверу список устройств: взломанный сервер может подсунуть свой «ключ устройства» и получить ключ воркспейса от агента админа (угроза T1). Защита — подтверждение новых устройств человеком или подпись ключей устройств — открытый вопрос; без неё E2E защищает от утечки базы, но не от активного взлома сервера.
- Пока ни одно устройство с ключом не в сети, новое устройство ждёт; окружение пишет, чего ждёт.
- Ключ на воркспейс: участник с ключом и доступом к шифртекстам другого проекта мог бы их прочитать, но сервер этих шифртекстов ему не отдаёт. Ключи на проект — если понадобятся.

## Открытые вопросы
- Подтверждение новых устройств и подпись изменений конфигурации ключом админа (защита от компрометации платформы, угроза T1).
- Автоматическая ротация после удаления участника на агенте админа.
