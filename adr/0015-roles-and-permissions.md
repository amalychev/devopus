# ADR-0015: Роли админ / тимлид / разработчик и права поверх ролей

**Статус:** Accepted (16.10.2026)

## Контекст

Владелец продукта описал три роли ([roles.md](../docs/product/roles.md)): админ (владелец бизнеса), тимлид (у тимлида несколько проектов, у проекта несколько тимлидов) и разработчик, который может или не может менять серверную среду в зависимости от выданных прав.

## Решение

1. **Админ** — владелец воркспейса, **один на воркспейс**; владение можно передать другому участнику (`devopus workspace transfer`). У одного пользователя может быть несколько воркспейсов. В воркспейсе админ может всё: проекты, сервисы, серверную среду, участников, тариф. Создаёт воркспейсы только админ.
2. **Тимлид** — роль **в проекте**. Пользователь может быть тимлидом нескольких проектов, у проекта может быть несколько тимлидов. Тимлид создаёт и настраивает проекты, управляет серверной средой своих проектов и приглашает разработчиков.
3. **Разработчик** — роль в проекте. По умолчанию работает с окружениями (поднимает, создаёт фичи, смотрит логи), но не меняет серверную среду. Дополнительные возможности — **права**, которые выдают админ или тимлид проекта.
4. **Права — отдельный список,** роли — их наборы по умолчанию. Права проверяет сервер воркспейса на каждом действии, одинаково для CLI и веб-интерфейса. Начальный список — в [roles.md](../docs/product/roles.md#права).
5. **Инвайты:** роль указывается сразу при создании. Админ приглашает тимлидов и разработчиков, тимлид — только разработчиков и только в свои проекты.

## Последствия

- Каждая команда CLI и каждый экран веб-интерфейса объявляют нужное право. Один список прав — одна точка проверки.
- В аудит-лог попадают изменения ролей, прав и серверной среды: кто, что и когда.
- Роли «только чтение» пока нет: три роли; добавим, если попросят пилоты.
