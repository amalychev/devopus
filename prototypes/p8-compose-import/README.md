# Прототип P-8: импорт `docker-compose.yml`

**Этап 0, одноразовый код.** Проверяет обязательную функцию первой версии из [specs/workspace-yaml.md](../../specs/workspace-yaml.md): импорт существующего compose-файла в `workspace.yaml` и экспорт обратно.

**Критерий из [плана этапа 0](../../docs/stage-0-plan.md):** ≥ 4 из 5 проектов импортируются без ручных правок. **Выполнен: 5 из 5 реальных продуктов.** Оговорка: по плану корпус должны были дать команды с интервью (V-4). Пока интервью нет, взяты открытые проекты. После интервью прогон нужно повторить на их файлах.

## Как устроено

1. **Загрузка** через `compose-go` v2.4 — ту же библиотеку, что у `docker compose`. Отрабатывают `extends`, якоря `x-`, подстановки `${…}`, `.env` проекта, `env_file`, профили.
2. **Перевод в черновик `workspace.yaml`:**
   - сервис с `build` → модуль, только с `image` → сервис;
   - `depends_on` → `uses`;
   - опубликованные порты отбрасываются, HTTP-входы становятся маршрутами (догадка);
   - переменные, похожие на секреты, → `${{ secrets.* }}`;
   - bind-монтирование кода модуля заменяется worktree;
   - образы без версии закрепляются по текущему digest.
3. **Проверка** по правилам спецификации.
4. **Обратный экспорт** в compose и проверка через `docker compose config`.

Уровни результата:

| Уровень | Значение |
|---|---|
| A | Черновик валиден, смотреть нечего |
| B | Черновик валиден и экспортируется. Есть пункты обзора: догаданные маршруты, секреты, профили, закреплённые образы, то, чего нет в формате v1. **Правка не нужна** |
| C | Есть блокер: черновик не проходит проверку, нужна ручная правка |
| N | Не целевой: в проекте нет ни одного `build`, только готовые образы. Разрабатывать и форкать нечего |

Корпус скачивается при запуске в `.corpus/` (вне git: у файлов свои лицензии). Черновики сохраняются в `.corpus/drafts/`.

```bash
go run .            # отчёт в stdout; последний прогон — results.md
```

## Что пришлось исправить в импортёре по ходу

| Проблема | Решение |
|---|---|
| Абстрактный базовый сервис в выключенном профиле (Immich) ломал загрузку со всеми профилями | Импортировать сервисы профилей по умолчанию, как `docker compose up`; остальные перечислять в обзоре |
| `.env` проекта не применялся: его читает CLI `docker compose`, а не `compose-go` (Sentry) | Импортёр сам читает `.env` рядом с compose-файлом |
| Склейка команды пробелами ломала кавычки (PostHog) | Аргументы экранируются |
| Docker Hub отвечал `429 Too Many Requests` на запрос digest после нескольких прогонов | Кэш digest'ов; при 429 закрепление откладывается — это пункт обзора, а не блокер |

## Выводы для спецификации `workspace.yaml`

1. **Лимит имени в 31 символ надуман.** У Sentry имена до 37 символов. Ограничение должно быть как у DNS-метки — 63 символа. Это был единственный блокер у реальных продуктов.
2. **`build` должен быть объектом:** `context`, `dockerfile`, `target`, `args`. Строки «папка с Dockerfile» не хватает ни одному реальному продукту.
3. **Сервисам нужен `uses`**, а не только модулям: инфраструктура тоже зависит друг от друга (Kafka → ZooKeeper, Sentry → ClickHouse).
4. **Нужны bind-монтирования файлов репозитория** (`./config/x.conf:/etc/x.conf`): 30 штук у Sentry, 14 у PostHog. Спецификация разрешала только именованные тома.
5. **Нужны необязательные сервисы** (аналог профилей): у Sentry и PostHog по 24–25 сервисов в профилях. Их не стоит поднимать в каждой фиче.
6. **Добавить в формат:** `entrypoint`, `healthcheck` у модулей, `tmpfs`, `ulimits`. Встречаются в 3 из 5 продуктов, реализуются тривиально.
7. **Свои сети compose (`networks`) можно спокойно сводить к одной сети окружения.** Встречаются почти везде, но служат только изоляции, которую Devcorb и так даёт.
8. **Правило «образ с явным тегом» нужно уточнить:** `redis:alpine` формально с тегом, но тег плавающий. Импортёр закрепляет такие образы по digest при импорте.
9. **Гибридный режим — открытый вопрос.** В PostHog основное приложение запускается на хосте, а compose держит только инфраструктуру. Devcorb форкать на хосте нечего — такой проект пока не целевой для фич. Нужно спросить на интервью, насколько это частая схема.
10. **Маршруты угадываются хорошо там, где вход один, и плохо там, где их несколько.** Импортёр должен предлагать маршруты, а не решать за пользователя.

## Что не проверено

- Корпус команд с интервью (V-4) — повторить прогон, когда он появится.
- Запуск импортированных стеков через агента: проверены валидность черновика и обратный экспорт, но не то, что стек поднимается.
- `include:` между файлами, compose с несколькими `-f` и `override.yml`.
