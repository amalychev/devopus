# Видение продукта

## Проблема

- Онбординг нового разработчика в продукт из нескольких модулей занимает дни: репозитории, версии рантаймов, БД, заглушки внешних сервисов, секреты, сиды.
- Инфраструктура у всех разная: у одного Mailtrap, у другого нет; кто-то на Redis, кто-то на файловом кэше → «у меня работает, а у тебя нет».
- Параллельная работа над несколькими ветками (и тем более несколькими AI-агентами) в одном локальном стеке невозможна: общие порты, общая БД, общее состояние.
- У команды нет видимости: кто над какой веткой работает, какие окружения подняты, где упала сборка.

## Решение

Единая веб-панель для всех dev-окружений команды, которые при этом работают **локально в Docker**, с отдельным URL на каждую ветку.

- **Веб-панель** — видимость и управление с любого устройства, включая телефон.
- **Агент** ставится на ноутбук, домашний ПК, VPS или сервер компании и приводит Docker к состоянию, описанному в панели.
- **Git worktree + свой хост** на каждую ветку и каждого AI-агента: `feature-x.myproject.localhost` с изолированным стеком и данными.
- **Одинаковая инфраструктура** у всех и онбординг за минуты.

**Формулировка для рынка:** «параллельные изолированные окружения на каждую ветку и каждого агента, с данными, для всей команды».

## Целевой клиент

| Роль | Кто |
|---|---|
| Покупатель | Тимлид или CTO — платит за скорость онбординга и отсутствие расхождений |
| Пользователь | Разработчик; AI-агенты (Claude Code, Codex) через MCP |
| Сегмент | Команды 5–100 разработчиков с продуктом из нескольких модулей: продуктовые компании, агентства с множеством клиентских проектов, команды, активно использующие AI-агентов |

## Конкуренты и отличия

Связки «командная веб-панель + локальный Docker-стек + worktree с данными» в одном продукте не найдено; по отдельности части существуют.

| Категория | Примеры | Чего не хватает |
|---|---|---|
| Локальные окружения | DDEV, Lando, Laravel Herd, Dev Containers | Уровень одного репозитория; нет командного слоя, секретов, данных |
| CLI для worktree | worktree-compose, wt, DevHub, dupe, worktrunk + Caddy | Однопользовательские, без веба и видимости |
| Оркестраторы AI-агентов | Conductor, Vibe Kanban и форки | Dev-сервер на порту, а не полный стек с БД, cron, очередями |
| Облачные среды | Codespaces, Gitpod, Coder | Код и база в чужом облаке, оплата за часы |
| PaaS | Railway, Render, Coolify | Продакшен, а не локальная разработка |

**Защищаемое преимущество** (сам факт «worktree + хост» легко повторить):

1. Быстрое клонирование данных на каждый worktree.
2. Автоусыпление и автоочистка окружений.
3. Маршрутизация между модулями по контексту фичи (request-level isolation на локальном Docker).
4. Интеграция с AI-агентами через MCP.
5. Командный слой с онбордингом и контролем расхождений.

## Бизнес-модель

Open-source агент и формат конфига — бесплатно для одного разработчика. Платно — командный слой в веб-панели, оплата за место. Цены — гипотеза для проверки на интервью.

| Тариф | Для кого | Что входит | Цена (гипотеза) |
|---|---|---|---|
| Free | Один разработчик | Агент, фичи, `*.localhost`, до 2 проектов | $0 |
| Team | Команда | Воркспейс, онбординг со снапшотом данных (актуальный + предыдущий), секреты, контроль расхождений, превью-ссылки | $15–25 / место / мес |
| Business | Компании с требованиями ИБ | SSO/SAML, аудит-лог, политики образов, управление снапшотами (история, именованные снапшоты, политики маскирования воркспейса, сканер ПДн) | $40+ / место |
| Enterprise | Крупные компании | Self-hosted панель (Helm), SLA, отчёт SOC 2 | Индивидуально |

**Почему агент open-source:** код, управляющий Docker на машине, безопасники захотят прочитать; открытость даёт бесплатный канал роста и снимает страх lock-in. Лицензия — Apache 2.0, см. [ADR-0010](../../adr/0010-agent-license.md).

## Метрики успеха

| Метрика | Цель / смысл |
|---|---|
| **Time-to-first-page** — от приглашения до первой открытой страницы | < 15 минут; главная метрика, показывается прямо в панели |

## Главная продуктовая гипотеза для проверки

Что болит сильнее и продаётся лучше: **онбординг и одинаковая инфраструктура** или **параллельные фичи для AI-агентов**? Ответ определяет акценты этапов 2–3 и маркетинг. Проверяется на этапе 0.
