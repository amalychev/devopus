# Глоссарий

Термины вложены: **воркспейс → проект → приложения и сервисы**; сервисы проекта подключаются к его приложениям. Пример: воркспейс — Google, проект — Google Drive, приложения — frontend и backend. Модель — с 16.10.2026 ([vision](vision.md)); во всей документации слова используются только в этих значениях.

## Модель

| Термин | Значение | Пример |
|---|---|---|
| **Воркспейс** (Workspace) | Компания админа: проекты, участники, права. Настройки и веб-панель — на сервере Devopus ([ADR-0016](../../adr/0016-workspace-server.md)) | Google, Acme |
| **Сервер воркспейса** | «Пульт»: программа `devopus server` хранит настройки, проверяет права, раздаёт настройки агентам, отдаёт веб-панель. Приложения на нём не запускаются. Облачный — на сайте Devopus; self-hosted — позже, на своём сервере | сайт Devopus или свой сервер |
| **Проект** (Project) | Продукт компании: приложения, которые работают вместе, и сервисы, на которых они работают. Роли тимлида и разработчика выдаются на проект | Google Drive, интернет-магазин |
| **Приложение** (Application) | Часть проекта, обычно один git-репозиторий; использует подключённые к нему сервисы проекта | `frontend`, `backend`, `admin`, `widget` |
| **Сервис** (Service) | Из чего собирается окружение: рантайм, хранилище, фоновый процесс или вспомогательный инструмент. У сервиса тип, версия и настройки. **Существует в рамках проекта и подключается к одному или нескольким его приложениям** (одна mysql — к backend и admin; php — к backend и admin) | `php 8.3`, `nodejs 22`, `mysql 8.4`, `redis`, `typesense`, `queue`, `cronjob`, `mailtrap` |
| **Серверная среда** | Настройки проектов, приложений и сервисов — то, чем управляют админ и тимлиды | «Drive: php 8.3 → backend, admin; mysql 8.4 → backend, admin; queue ×2 → backend» |
| **Переопределение** (Override) | Личное изменение настроек в файле `devopus.local.yaml` в папке приложения (в git не попадает), если разработчик не согласен с серверной средой. Разрешено правами и политикой проекта, видно в веб-панели ([ADR-0013](../../adr/0013-config-on-workspace-server.md)) | `php: 8.4` у себя |

## Люди и доступ

| Термин | Значение |
|---|---|
| **Пользователь** | Аккаунт в Devopus по email; один на все воркспейсы |
| **Админ** | Владелец воркспейса, один на воркспейс (владение можно передать); может всё в нём ([roles](roles.md)) |
| **Тимлид** | Роль в проекте: настраивает проект, его приложения и сервисы, приглашает разработчиков |
| **Разработчик** | Роль в проекте: работает с окружениями; остальное — по выданным правам |
| **Право** (Permission) | Разрешение на действие (`services.manage`, `members.invite`…); роли — наборы прав по умолчанию |
| **Инвайт** | Приглашение по email с ролью, выданное админом или тимлидом |
| **Auth** | Сервис аккаунтов и входа: email + одноразовый код, access и refresh токены ([ADR-0014](../../adr/0014-auth-service.md)) |
| **Сессия** | Вход пользователя на устройстве; живёт, пока ей пользуются, и отзывается |
| **Тарифный план** | Free, Team, Self-hosted, Enterprise; выбирается админом при регистрации ([vision](vision.md#бизнес-модель)) |

## Окружения

| Термин | Значение | Пример |
|---|---|---|
| **Окружение** (Environment) | Запущенный проект (его приложения и сервисы) на конкретной машине | Google Drive на ноутбуке Анны |
| **Базовое окружение** | Окружение проекта с основных веток (`main`); у каждой машины одно на проект. Никогда не засыпает | `drive.localhost` |
| **Фича** (Feature) | Задача в проекте: приложения, которые меняются, с одной веткой; получает своё окружение | PAY-123: backend + frontend |
| **Форк** | Приложение внутри фичи: worktree + свои контейнеры + при необходимости клон БД | backend в PAY-123 |
| **Staging / Production** | Окружение проекта на собственном сервере админа, где стоит агент (позже) | `drive.staging.google.dev` |
| **Агент** | Программа на машине (ПК разработчика или сервер админа), которая по настройкам приводит Docker, git и прокси к нужному состоянию; единственное место, где запускаются приложения | `devopus agent` |
| **Устройство** (Device) | Машина с агентом, привязанная к пользователю | ноутбук разработчика, сервер админа для staging |
| **Локальная панель** | Веб-интерфейс агента на `127.0.0.1` для окружений этой машины ([ADR-0012](../../adr/0012-devopus-cli-control-point.md)) | `devopus panel open` |
| **Веб-панель воркспейса** | Те же действия, что в CLI, для воркспейса целиком; на сайте Devopus | этап 3+ |
| **Демо-воркспейс** | Воркспейс с проектом из [examples/demo](../../examples/demo) для разработки и отладки Devopus; режима без воркспейса нет | — |
| **AI-агент** | Кодинг-ассистент, работающий с фичами через MCP | Claude Code, Codex |

## Технические термины

| Термин | Значение |
|---|---|
| **Желаемое состояние** (DesiredState) | Что должно быть запущено на устройстве; приходит с сервера воркспейса, версионируется ревизией |
| **Фактическое состояние** | Что реально запущено; агент сообщает в `StatusReport` |
| **Расхождение** (drift) | Разница между серверной средой и окружением участника: переопределение, старая версия, отключённый сервис |
| **Золотая копия** | Копия базы базового окружения, из которой клонируются базы фич |
| **Simple / Contextual Isolation** | Фича со своими копиями зависимых приложений / маршрутизация по контексту фичи (W3C Baggage) |
| **ID окружения** | Стабильный идентификатор во всех Docker-ресурсах; слаг — только в URL |

## Переход от модели этапа 1

Код этапа 1 (локальный движок, v0.1.0) использует прежние слова. Соответствие простое — меняется только «модуль»:

| Этап 1 (`workspace.yaml`) | Сейчас |
|---|---|
| Проект (`project:` в `workspace.yaml`) | Проект — без изменений |
| Модуль (`modules:`) | **Приложение** |
| Сервис (`services:`) | Сервис проекта, подключённый к приложениям (`uses:`) |
| `runtime:` модуля, `workers:`, `cron` | Сервисы проекта типов рантайм, `queue`, `cronjob`, подключённые к приложению |
| — | Воркспейс — новый уровень над проектами |
| `workspace.yaml` в репозитории — источник правды; работа без сервера | Настройки на сервере воркспейса; YAML — просмотр и личный `devopus.local.yaml`; режима без воркспейса нет |
| `overrides.allowed` | Политика переопределений проекта + право `overrides.use` |
