# Роли и права

Решение — [ADR-0015](../../adr/0015-roles-and-permissions.md). Иерархия: воркспейс (Google) → проект (Google Drive) → приложение (frontend, backend) → сервисы. Права проверяет сервер воркспейса на каждом действии, одинаково для CLI и веб-интерфейса.

## Роли

| Роль | Где действует | Кто | Главное |
|---|---|---|---|
| **Админ** | Воркспейс целиком | Владелец бизнеса | Один на воркспейс; владение можно передать. Создаёт воркспейсы (у него их может быть несколько) и проекты в них, управляет серверной средой, участниками и тарифом |
| **Тимлид** | Проект | Руководитель разработки проекта | Создаёт и настраивает проекты, их приложения и сервисы, управляет серверной средой своих проектов, приглашает разработчиков. У тимлида может быть несколько проектов, у проекта — несколько тимлидов. Создавший проект тимлид становится его тимлидом |
| **Разработчик** | Проект | Участник команды | Работает с окружениями всех приложений проекта. Менять серверную среду может, только если ему выдано право |

Пользователь один на все воркспейсы ([ADR-0014](../../adr/0014-auth-service.md)): в одном воркспейсе он может быть админом, в другом — разработчиком.

## Права

Роли — это наборы прав по умолчанию. Админ и тимлид проекта могут выдать разработчику дополнительные права в пределах своих.

| Право | Что разрешает | Админ | Тимлид (своих проектов) | Разработчик |
|---|---|---|---|---|
| `workspace.manage` | Настройки воркспейса, тариф, передача владения, удаление | ✓ | — | — |
| `workspace.create` | Создать воркспейс | ✓ (только админ) | — | — |
| `project.create` | Создать проект в воркспейсе | ✓ | ✓ | — |
| `project.configure` | Настройки проекта: домен, политика фич и переопределений | ✓ | ✓ | по выдаче |
| `apps.manage` | Приложения проекта: добавить, репозиторий, ветка, маршруты, хуки | ✓ | ✓ | по выдаче |
| `services.manage` | Сервисы проекта: добавить, версии, настройки, к каким приложениям подключены | ✓ | ✓ | по выдаче |
| `servers.manage` | Серверы админа с агентом: staging и production (позже) | ✓ | ✓ (проекта) | по выдаче |
| `secrets.manage` / `secrets.read` | Секреты проекта | ✓ / ✓ | ✓ / ✓ | — / ✓ |
| `members.invite` | Инвайты: админ — тимлидов и разработчиков; тимлид — разработчиков в свои проекты | ✓ | ✓ (только разработчиков) | — |
| `members.manage` | Роли и права участников, удаление | ✓ | ✓ (разработчиков проекта) | — |
| `overrides.use` | Переопределять конфигурацию у себя личным файлом `devopus.yaml` | ✓ | ✓ | ✓ в рамках политики проекта |
| `env.use` | Поднимать окружения, создавать фичи, логи, `exec`, данные своих окружений | ✓ | ✓ | ✓ |

## Инвайты

- Инвайт создаёт админ или тимлид; роль указывается сразу.
- Админ может пригласить **тимлида** или **разработчика** (в воркспейс и в выбранные проекты).
- Тимлид может пригласить только **разработчика** и только в свои проекты.
- Инвайт привязан к email и имеет срок жизни. Принять его можно после входа с этим email: `devopus invite accept <код>` или по ссылке.
- Отозвать инвайт можно до принятия; удалённый участник теряет доступ сразу, его устройства отзываются.

## Решено (16.10.2026)

- Админ — один на воркспейс, владение можно передать (`devopus workspace transfer`).
- Воркспейсы создаёт только админ; тимлид создаёт и настраивает проекты внутри, их приложения и сервисы.
- Роли выдаются на проект: разработчик проекта Google Drive работает со всеми его приложениями.
- Роли «только чтение» пока нет.
- Доступ к git-репозиториям новичку выдают как обычно (GitHub/GitLab); агент клонирует с его ключами, а Devopus проверяет доступ и подсказывает, если его нет.
