Заполнять в день интервью, по одной на разговор. Хранить в `docs/stage-0/interviews/NN-компания.md` (без персональных данных, если документ будет общим).

Языки: … · БД: … · Очереди: … · ОС (доля Windows): … · Runtime: …

## Онбординг (H1)

## Таблица оценок

Сводная таблица — в [tracker.md](tracker.md). Для решений по гипотезам считаем:

| Показатель | Как считается |
|---|---|
| Боль онбординга | Медиана Б4 по всем интервью; доля с онбордингом > 1 дня |
| Боль параллельной работы | Медиана В4; доля с ≥ 2 ветками раз в неделю |
| AI-параллельность | Доля с ≥ 2 агентами одновременно сейчас или в планах на 3 месяца |
| Главная боль | Сколько раз (а) и (б) стоят первыми в Е2 |
| Цена | Медиана «нормальной» цены Ж2; доля ≥ $15 |
| Покупатель | Доля, где решает тимлид/CTO |
| Блокер безопасности | Доля «запретят» в Д2 |
| Windows | Доля разработчиков на Windows в целевых командах |
| Гибридный режим | Доля «приложение на хосте» в Г2 |

## Правила решения

Правила для каждой гипотезы — в [hypotheses.md](hypotheses.md). Дополнительно:

- **Промежуточный синтез после 10 интервью.** Если H1 и H2 обе явно не подтверждаются (медиана боли ≤ 2) — остановить серию и пересмотреть позиционирование, а не добирать 20.
- **Готовность к пилоту** засчитывается, только если есть подписанное LOI ([loi.md](loi.md)), конкретный человек, который будет пользоваться, и проект, подходящий под MVP: macOS или Linux, Docker, Postgres или MySQL, compose или описуемый стек.
- **Итоговый документ серии** — `docs/stage-0/findings.md`: вердикт по каждой гипотезе с цифрами, решение по ADR-0008 и ADR-0010, изменения в roadmap и PRD MVP.
