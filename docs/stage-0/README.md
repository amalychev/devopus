# Этап 0: комплект для валидации

Технические прототипы этапа 0 готовы ([отчёт](report.md)). Чтобы закрыть этап, осталась продуктовая валидация: **20 интервью и 5 команд, готовых к пилоту**. Здесь всё, что для этого нужно.

| Файл | Зачем |
|---|---|
| [hypotheses.md](hypotheses.md) | Что проверяем на интервью и по какому правилу решаем |
| [screener.md](screener.md) | Кого зовём: квоты по сегментам и критерии отбора |
| [outreach.md](outreach.md) | Тексты приглашений: первое сообщение, напоминание, ответ на «что это» |
| [interview-guide.md](interview-guide.md) | Сценарий интервью на 45 минут с привязкой вопросов к гипотезам |
| [synthesis.md](synthesis.md) | Карточка интервью, таблица оценок, правила принятия решений |
| [tracker.md](tracker.md) | Таблица 20 интервью и воронки до пилота |
| [pilot.md](pilot.md) | Что получает пилотная команда, что от неё нужно, метрики пилота |
| [loi.md](loi.md) | Письмо о намерениях: что значит «готовы к пилоту» |
| [report.md](report.md) | Итоговый отчёт этапа 0: что закрыто, что осталось и кто делает |

## Порядок работы

1. Заполнить `screener.md` → список из 30–40 кандидатов (часть откажется).
2. Разослать приглашения по `outreach.md`, вести воронку в `tracker.md`.
3. Провести 20 интервью по `interview-guide.md`, после каждого заполнить карточку из `synthesis.md` — в тот же день.
4. После 10 интервью — промежуточный синтез: не пора ли менять вопросы.
5. Командам с оценкой боли ≥ 4 и подходящим стеком предложить пилот (`pilot.md`), договориться о LOI (`loi.md`).
6. Попросить у пилотных команд compose-файлы (V-4) и прогнать на них импорт P-8.
7. Подвести итог по правилам из `hypotheses.md` и закрыть открытые ADR.

**Критерий перехода к этапу 1:** 5 команд подписали LOI.
