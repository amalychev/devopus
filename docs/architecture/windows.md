# Windows и WSL2 (P1, этап 3)

На Windows три среды: Windows (браузер и IDE), WSL2 (Linux-файлы) и Docker (контейнеры). Проблемы возникают на их границах, поэтому агент на Windows состоит из двух компонентов.

## Двухкомпонентный агент

| Компонент | Задачи | Права |
|---|---|---|
| **Служба Windows** | Установка, DNS и NRPT, сертификаты, `hosts`, порты, интеграция с ОС, Defender-исключения | Нужные для этих задач (админ при установке) |
| **Агент внутри WSL2** | git worktree, Docker, volumes, Envoy, контейнеры — как обычный Linux-агент | Пользовательские |

Общаются по локальному сокету. Сложнее в разработке, но снимает большую часть проблем с путями и ФС. Код хранится в ФС WSL2; IDE получает путь через `\\wsl$`.

## Сеть Windows ↔ WSL2

Симптом: окружение открывается внутри WSL2, но не из браузера в Windows, или отваливается после сна ноутбука. Причина: в NAT-режиме проброс localhost работает только для IPv4 и нестабилен.

По убыванию предпочтительности:
1. Envoy — контейнер в Docker Desktop с опубликованными 80/443 → порт открыт на стороне Windows.
2. `networkingMode=mirrored` в `.wslconfig` (Windows 11 22H2+) — агент предлагает включить при установке.
3. NAT-режим с проверкой проброса и предупреждением в панели.

## Таблица проблем

| Проблема | Решение |
|---|---|
| Bind mount из `C:\Projects` в разы медленнее | Код в ФС WSL2; IDE — через `\\wsl$` |
| File watching не срабатывает из `/mnt/c` | Тот же переход в WSL2 (inotify не проходит границу) |
| CRLF/LF ломает скрипты в контейнерах | `.gitattributes` в проекте и `core.autocrlf=input` при клонировании |
| Регистр имён: `User.php` и `user.php` | Проверка конфликтов имён при клонировании |
| Defender замедляет сборку | Диагностика и предложение исключений для папок проекта, `node_modules`, `vendor` |
| IDE не видит файлы | WSL-интеграция VS Code, JetBrains Gateway |
| Docker Desktop выключен | Health check и понятная ошибка с кнопкой запуска |
| Резолвинг внутри WSL2 | WSL генерирует свой `resolv.conf`; агент настраивает DNS для `.localhost` отдельно |
| Зарезервированные порты (Hyper-V/WinNAT) | См. [local-networking.md](local-networking.md#зарезервированные-порты-windows) |
| `*.localhost` не резолвится вне браузера | DNS на :53 + NRPT, см. [local-networking.md](local-networking.md#2-резолвинг-localhost-p0) |
| Отдельное хранилище CA в WSL2 | Агент ставит CA и в Windows, и в WSL2 |
