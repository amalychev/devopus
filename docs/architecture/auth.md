# Auth: аккаунты, вход и токены

Решение — [ADR-0014](../../adr/0014-auth-service.md). Роли и права — не здесь, а на сервере воркспейса ([ADR-0015](../../adr/0015-roles-and-permissions.md)).

## Что делает сервис

| Функция | Как |
|---|---|
| Регистрация | Email → одноразовый код (OTP) в письме → аккаунт. Админ выбирает тарифный план: пока только Free, Self-hosted и платные — позже |
| Вход | Email + OTP в терминале. Где есть браузер — как у CLI AI-агентов: страница входа и обратный вызов на `127.0.0.1` (OAuth 2.0 Authorization Code + PKCE). Без браузера — device flow (RFC 8628) |
| Токены | Access (JWT, 15 минут) и refresh (непрозрачный, с ротацией) |
| Сессии | Одна на устройство; список и отзыв |
| Ключи | JWKS с публичными ключами подписи, ротация без простоя |
| Реестр воркспейсов | Какие воркспейсы есть у пользователя и где их серверы (облачные и self-hosted) |

Сервис не знает ролей и прав: их проверяет сервер воркспейса.

## Регистрация и вход в CLI

```text
$ devopus register
Email: admin@acme.dev
Code sent to admin@acme.dev (valid 10 minutes): 482913
Plan: Free (Self-hosted and paid plans are coming)
✓ Signed in as admin@acme.dev

$ devopus login                 # браузер: откроет страницу входа
$ devopus login --email         # без браузера: email и код в терминале
$ devopus login --device        # на сервере по SSH: код и ссылка для другого устройства
```

## Токены и сессии

| | Access | Refresh |
|---|---|---|
| Формат | JWT, подпись Ed25519 | Случайные 256 бит; в базе — хеш |
| Срок | 15 минут | Сессия: 30 дней без активности, 90 дней всего |
| Содержимое | `sub` (пользователь), `sid` (сессия), `exp`, `aud` (воркспейс или `devopus`) | — |
| Где на устройстве | В памяти процесса | Keychain (macOS), Secret Service (Linux); файл `0600` — только если хранилища нет |
| Обновление | По refresh-токену | Одноразовый: каждое обновление выдаёт новый, старый гаснет. Повторное использование старого отзывает всю сессию |

**«Живёт, пока пользуются»:** каждое обновление токена сдвигает окно бездействия. Разработчик, который работает каждый день, входит заново раз в 90 дней.

**Отзыв:** `devopus auth sessions` и `devopus auth revoke <id>`, выход — `devopus logout`. Удаление участника из воркспейса действует сразу: сервер воркспейса проверяет членство на каждом запросе, а не по токену.

## Агенты

- **Агент на ПК** работает от имени пользователя: CLI передаёт ему сессию при `devopus agent install`, агент обновляет токены сам.
- **Агент на сервере админа** (staging, production — позже) получает **токен устройства** (`devopus agent install --server`). Это не пользователь; токен ограничен воркспейсом и отзывается вместе с устройством.

## Защита

- OTP: 6 цифр, живёт 10 минут, 5 попыток; лимиты на email, IP и устройство; одинаковый ответ для существующих и новых email.
- Вход через браузер — только с PKCE, обратный вызов — только на `127.0.0.1` со случайным портом и `state`.
- Ключи подписи — в KMS или HSM облака, ротация по расписанию; JWKS кешируется серверами воркспейсов.
- Все входы, выходы, отзывы и смены плана — в журнале безопасности аккаунта.

## Открытые вопросы

- Self-hosted без интернета: Auth внутри инсталляции (Enterprise) или кеш ключей и офлайн-период.
- Почтовый провайдер и домен отправителя (зависит от выбора домена продукта).
- Вход в веб-интерфейс: тот же OTP по email или сразу ссылка «magic link».
