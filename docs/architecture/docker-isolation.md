# Изоляция Docker (P0)

Каждое окружение получает собственное пространство имён по стабильному ID, а модули не публикуют порты на хост. Тогда две фичи физически не могут перезаписать ресурсы друг друга.

## Соглашения об именовании

| Ресурс | Шаблон | Пример |
|---|---|---|
| ID окружения | ULID/короткий стабильный ID, не зависит от имени ветки | `01JA8…` → `e7k2m9` |
| Compose project | `<project>-env-<id>` | `shop-env-e7k2m9` |
| Volume | `<project>-<env-id>-<name>` | `shop-e7k2m9-mysql` |
| Метки | `com.devcorb.project=<id>`, `com.devcorb.env=<id>`, `com.devcorb.module=<name>` | — |
| Слаг (только URL) | из ветки, с проверкой уникальности в проекте | `pay-123` |
| Worktree | `<data-dir>/<project>/<env-id>/<module>` | — |

Человекочитаемый слаг используется **только в URL**. `feature/a-b` и `feature/a_b` дают одинаковый слаг → при коллизии добавляется суффикс, а ресурсы всё равно разнесены по ID.

## Таблица проблем

| Проблема | Что произойдёт | Решение |
|---|---|---|
| Конфликт имён контейнеров | Две фичи создают `mysql` | Уникальный Compose project name `shop-env-<id>` |
| Конфликт volumes | Окружения перезаписывают данные друг друга | Namespace volumes по ID проекта и окружения; метки `com.devcorb.env=<id>` для GC |
| Конфликт портов на хосте | Два модуля слушают 3000 | Порты модулей на хост **не публикуются**; наружу ходит только Envoy. Исключение — явный override `ports` |
| Коллизия слагов | `feature/a-b` и `feature/a_b` | Стабильный ID во всех ресурсах, слаг только в URL с проверкой уникальности |
| Исчерпание пула адресов | ~30 сетей → `could not find an available, non-overlapping IPv4 address pool` | `default-address-pools` с подсетями /24 или одна сеть на проект с алиасами |
| Пересечение с VPN | 172.17–172.31 совпадают с корпоративной сетью | Агент проверяет маршруты и выбирает пул без пересечений, например `10.213.0.0/16` |
| Runtime отсутствует/выключен | Агент не может поднять окружение | Preflight: Docker Desktop, OrbStack, Colima или Podman; понятная ошибка и инструкция |
| Различия runtime | Podman/Colima иначе работают с `host.docker.internal`, сокетом, пробросом портов | Слой абстракции над runtime + интеграционные тесты на каждом |

```json
{
  "default-address-pools": [
    { "base": "10.213.0.0/16", "size": 24 }
  ]
}
```
256 сетей вместо ~30.

## Топология сетей (предложение)

Одна сеть на **проект** (`shop-net`), а не на окружение — экономит пул адресов. Изоляция обеспечивается тем, что:
- контейнеры разных окружений получают алиасы, уникальные по ID (`payments.e7k2m9`);
- логические имена (`payments`) резолвятся в листенер Envoy, а не в контейнер напрямую;
- Envoy подключён ко всем сетям проектов.

Альтернатива (сеть на окружение) проще для изоляции, но упирается в пул. Решение фиксируется в [ADR-0006](../../adr/0006-docker-network-topology.md) после прототипа.

## Сборка мусора

GC удаляет только ресурсы с метками `com.devcorb.*`, для которых нет записи в желаемом состоянии. Ресурсы без меток агент не трогает никогда. Volumes с данными удаляются только вместе с удалением окружения (после проверки worktree).

## Поддерживаемые runtime'ы

| Runtime | ОС | Особенности |
|---|---|---|
| Docker Desktop | macOS, Windows, Linux | Лицензия для крупных компаний; VM с ext4 (нет reflink) |
| OrbStack | macOS | Быстрая ФС; рекомендуемый на Mac |
| Colima | macOS, Linux | Нужно учитывать сокет и `host.docker.internal` |
| Podman | Linux, macOS | Rootless по умолчанию → привилегированные порты, сокет-совместимость |
| Docker Engine | Linux | Нативно, rootful/rootless |
